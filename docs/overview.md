# 思维链工程总纲（CoT Engineering Overview）

> 本文档既是给人读的方法论，也是给 AI 读的**元指令**。把它喂给任意支持思考的模型，模型就能据此为新的任务类型生成结构合理的思维链模板。

---

## 1. 定位

**思维链工程是提示词工程的一个分支。**

| 层次 | 管什么 | 回答的问题 |
|------|--------|-----------|
| 提示词工程 | 做什么 | "任务是什么、要什么产出、有什么约束" |
| **思维链工程** | **怎么想** | "思考分成哪几步、谁在思考、按什么顺序、谁拍板" |
| Agent 工程 | 怎么执行 | "多轮调用、工具、外部状态怎么编排" |

普通提示词只约束模型的**输出**；思维链工程进一步约束模型的**思考过程**。

---

## 2. 为什么思考可以被设计

模型的一次回答包含两部分：**思考过程**（通过思考标签组织）与**最终回答**。关键事实：

1. 思考是模型自回归生成的文本——**前面写下的思考，会引导后面的思考**。
2. 因此，如果提示词预先规定了思考的**结构**，模型会倾向于沿用这个结构去展开思考。
3. 这意味着思考不是模型固定的黑盒习惯，而是一个**可塑的文本对象**。

这就是"思维链工程"成立的根基：**我们可以把"思考"本身当作设计对象**。

---

## 3. 三种塑形方式

思维链塑形有三种方式，按"要不要标签、控制多具体"区分。核心是**直接控制思考方式**（方式二），标签只是可选的格式化外壳。

### 方式一：有结构（显式标记）

思考被组织成带标记的结构，标记可见、可解析、可检查。下面两种可分开用。

#### 1a. 说话人标记（多角色）

把思考组织成**多个说话人的对话**，标记是"谁在说"：

```
[判断] → [稳] → [快] → [争执] → [裁定]
```

- **关键**：标记是说话人，且 `[裁定]` 直接决定输出内容（谁赢谁说话 / 谁的方案）。
- **适合**：角色扮演、决策权衡、有真实分歧的任务。
- **实测**：角色扮演 25/25（100%）；代码 build 配合 `reasoning_effort=max` 15/15。
- 模板见 [`templates/roleplay-dual-persona.md`](templates/roleplay-dual-persona.md)、[`templates/code-build.md`](templates/code-build.md)。

#### 1b. 路由式（分类 → 分派流程）

**入口阶段先分类，再路由到不同子流程**：

```
[判断] 任务类型（数学 / 技术方案 / 决策 / 创意 / 故障诊断 / ...）
   ├─ 数学      → [数学解题流程]（步骤式：理解→探索→推导→验证）
   ├─ 技术方案  → [评审流程]（多角色各查各的，不辩论）
   ├─ 决策/争议 → [辩论流程]（多角色对抗，强制轮次）
   ├─ 创意      → [脑暴流程]（发散→收敛）
   └─ 故障      → [诊断流程]（假设→排除→定位）
```

- **关键**：入口分类决定走哪条流程，一条 system prompt 覆盖多类任务。
- **适合**：多任务类型混合的场景，或需要"先分型再对症"的任务。
- 这是"状态机"思想的落地：入口做分类决策，分类后进入不同分支。

### 方式二：直接思考控制（无标记，核心）

**不需要管标签，直接命令模型"怎么想"，验证看思维链内容是否按命令执行。**

- 命令**思考顺序**：先理解 → 再方案 → 再风险 → 再验证。
- 命令**思考角度**：从多个立场审视（如风险 + 机会两面）。
- 命令**思考决策**：最后必须给出明确结论（做 / 不做）。
- 用自然语言思考，**不要求任何标记**。

示例：

```
思考时必须按以下方式：
1. 先列出这个方案的风险（至少 3 条）。
2. 再列出机会（至少 3 条）。
3. 对比后给出明确结论：做还是不做。
用自然语言思考，不要写任何标记。
```

- **关键**：控制的是"想什么、怎么想"，不控制"带不带标签"。
- **实测**：模型确实按命令的顺序/角度思考（即使不写标记），见 [`findings.md`](findings.md) 单人多轮实验。
- **优点**：最稳定、最省 tokens、无泄漏风险，是三种方式里最普适的。

### 方式三：软引导（口癖 / 风格）

只塑造思考的**语言风格**，不控制具体步骤。例如把 `we need to` 与第一人称情态动词（`I'll` / `I can` / `I should`）写进规则各处，思维链就变成第一人称风格。

- **关键**：只塑风格，不控步骤。
- **适合**：通用场景，尤其不想留标记、也不想约束具体思考路径时。
- 参考：[scp3500/oh-we-need](https://github.com/scp3500/oh-we-need)（DeepSeek V4 `we need to` 口癖引导）。

## 4. 核心规律（实验验证）

**思维链标记的命中率，取决于「思考是否直接决定输出」。**

| 场景 | 命中率 | 原因 |
|------|--------|------|
| 角色扮演（谁赢谁说话） | 100%（25/25） | 不走到裁定就无法输出 |
| 代码（辩完还是要写代码） | 17%~100% | 辩论是"过场"，可跳过 |

关键变量：`reasoning_effort=max`（默认 `low` 下命中率仅 ~17%）、轮数强制、裁定强绑定输出。完整数据见 [`findings.md`](findings.md)。

## 5. 与相邻概念的边界

| 概念 | 关系 |
|------|------|
| 思维链（CoT） | 一个**技巧**："让模型一步步想"。思维链工程把它**系统化、模板化、领域化**。 |
| 提示词工程 | 父领域。思维链工程是其下专门约束"思考结构"的子分支。 |
| Agent 工程 | 相邻领域。Agent 管多轮执行与工具；思维链工程在**单轮内**约束思考。二者可组合，但边界要清晰。 |

---

## 6. 关键约束（必读）

1. **思考标签表述模糊化**：提及模型的思考标签时，只用"`<think>` 思考标签"这类模糊措辞，**不描述标签的包裹 / 分隔 / 输出机制**。否则模型可能把标签当成要输出的内容，泄漏到最终回答里。
2. **位置分离，而非"隐藏标记"**：说"在 think 标签内完成、不要留在最终回答里"，不要说"不要输出标记"——后者会被模型误解为"全部隐藏"，导致标记连思考里都不写。
3. **标记要成为"说话人"，不要成为"流程步骤"**：单人的流程标记（`[第1轮]`）必被省略；多说话人标记（`[稳][快]`）模型被迫写。
4. **思考要直接决定输出**：让 `[裁定]` 的结果直接决定正文内容，否则模型随时可以跳过思考结构。
5. **环境先行**：命中率对运行环境敏感（客户端默认提示词、`reasoning_effort` 档位）。评估效果前先固定环境。

## 7. 元指令（教 AI 生成新模板）

> 以下内容面向"读了这个文档后要生成新模板的模型"。语言为指令式。

当你需要为某个任务类型设计一个思维链模板时，按以下步骤执行：

1. **先选形式**：
   - 任务有"多个立场拉扯、需要裁定" → 用**形式 A（说话人标记）**。
   - 任务需要"先分型、再对症"，或一条提示词覆盖多类任务 → 用**形式 B（路由式）**。
2. **分解阶段**：把该任务的推理过程拆成 3–7 个语义不重叠的阶段，每个阶段只有一个目标。
3. **设计标记或路由**：
   - 形式 A：为每个说话人/立场取简短标记（`[稳]` `[快]`），并设计一个 `[裁定]` 拍板。
   - 形式 B：设计入口 `[判断]`（分类规则）+ 每个分支的子流程。
4. **保证思考决定输出**：让裁定/路由结果直接决定最终回答的内容或形式。
5. **组装提示词块**：附一段可直接粘贴的 system prompt，遵守第 6 节的关键约束。
6. **标注环境要求**：注明需要 `reasoning_effort=max` 或特定客户端设置。

生成结果应包含：形式选择、阶段/标记清单、路由规则（如有）、可直接粘贴的提示词块、环境要求。
