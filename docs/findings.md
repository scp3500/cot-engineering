# 实验发现（Findings）

> 本文档记录本项目在 DeepSeek V4 上做的全部思维链塑形实验、数据与结论。实验环境：官方 API 直调（`https://api.deepseek.com`），模型 `deepseek-v4-flash`，`thinking` 开启，请求不含任何客户端默认提示词（已核实 `models.json` 无干扰项）。

---

## 1. 一句话结论

> **思维链标记的命中率，取决于「思考是否直接决定输出」。**

- 思考**直接决定输出**（如角色扮演里"谁赢谁说话"）→ 标记稳定命中（实测 25/25）。
- 思考**不直接决定输出**（如代码任务里"辩完还是要写代码"）→ 标记命中飘忽，需靠额外手段拉高。

---

## 2. 核心实验数据

### 2.1 不同配方在代码任务上的命中率

| 配方 | build | fix | 说明 |
|------|-------|-----|------|
| 尖括号标签 `<understand>` | 0/5 | 0/5 | 被当作 XML 标签，模型"在心里做" |
| 方括号 + "不要输出标记" | 0/5 | 0/5 | "不要输出"被理解为"全部隐藏" |
| 单人多轮 `[第1轮]` | 0/12 | 0/12 | 无说话人，标记必被省略 |
| 伪角色（我/审视） | 3/9 | 6/9 | 有说话人但不够逼真 |
| **双工程师 + 轮数 + max** | **15/15 (100%)** | 3/15 | build 稳定，fix 仍飘 |

### 2.2 角色扮演任务上的命中率

| 配方 | 结果 |
|------|------|
| **双人格争抢（爱理）** | **5 次全命中 25/25，零泄漏**（默认参数，无需 effort/轮数） |

### 2.3 `reasoning_effort` 的影响（单测）

| effort | 命中率 |
|--------|--------|
| 默认（low） | 17% |
| `max` | 67% |

`reasoning_effort=max` 是提高代码任务命中率最有效的单变量。

## 3. 稳定命中的配方

### 配方 A：角色扮演 / 对话 / 决策类（已验证 100%）

**双人格争抢**。核心要素：

1. 两个**对立人格**（各有性格、动机、说话方式）
2. 标记是**说话人**：`[判断] [理] [爱] [争执] [裁定]`
3. `[裁定]` 谁赢 → 正文用谁的语气说话（**思考直接决定输出**）
4. 明确"在 think 标签内完成，不要留在最终回答里"
5. 字数限制（≤30 字）

模板见 [`templates/roleplay-dual-persona.md`](templates/roleplay-dual-persona.md)。

### 配方 B：代码 / 产出类（build 实测 100%，fix 不稳定）

**双工程师辩论 + 轮数 + max effort**。在配方 A 基础上增加：

1. `reasoning_effort=max`
2. **轮数强制**（至少 3 轮，每轮两个角色必须发言）——防止"一句话糊弄"
3. **裁定强绑定输出**——"`[裁定]` 选定方案后，最终代码必须严格按该方案实现，不得混合"

模板见 [`templates/code-build.md`](templates/code-build.md)、[`templates/code-fix.md`](templates/code-fix.md)。

---

## 4. 为什么这些要素有效（机理）

| 要素 | 机理 |
|------|------|
| 方括号 `[xx]` | 中性标记，不被当作 XML/HTML 标签，模型不抑制 |
| 多说话人 | 标记是"谁在说"的标识，不写就分不清，**被迫写** |
| 思考直接决定输出 | 不走到 `[裁定]` 就无法确定输出，**被迫走完** |
| 轮数强制 | 一句话糊弄不过去，必须展开 |
| `reasoning_effort=max` | 文本前缀鼓励"彻底思考"，模型更认真 |
| few-shot 示例 | 直接展示标记长什么样，模型照格式模仿 |
| "不要留在最终回答里" | 位置分离，而非"不要输出标记"（后者会被误解为全隐藏） |

## 4.5 标签命中 vs 思考方式引导（关键区分）

本项目早期把"标签命中率"当作核心指标，这是跑偏。真正重要的是**思考方式是否被引导**：

| 实验 | 标签命中 | 思考方式是否被引导 |
|------|---------|------------------|
| 单人多轮 `[第1轮]` | 0/12 | ✅ 模型按"理解→方案→风险→验证"顺序思考 |
| 双工程师辩论 | 33%~100% 飘 | ✅ 模型确实从"稳 vs 快"两立场交锋 |
| 口癖引导 | 无标签 | ✅ 思维链全程 we need to 风格 |

**结论：思考方式被引导是稳定的，飘的只是"标签"这个外壳。**

- 验证标准应从"有没有标签"改为"思考内容是否按命令执行"。
- 标签只剩下**可解析**的价值（方便程序化定位每一步），不是核心。
- 因此**方式二（直接思考控制，无标记）是最普适的核心方式**，详见 [`overview.md`](overview.md)。

## 4.6 方式二实测：裸问 vs 直接思考控制（LeetCode 42 接雨水）

同一道经典算法题（LeetCode 42 接雨水），对比无 system（bare）与方式二（direct，命令"先分析 → 列至少 2 种解法 → 分析复杂度 → 权衡 → 实现验证"）：

| effort | 方式 | 思维链 | 耗时 | 结果 |
|--------|------|--------|------|------|
| low | bare | 848 字 | 5.5s | 双指针，正确 |
| low | direct | 17491 字 | 66.7s | 双指针，正确 |
| max | bare | 52509 字 | 138.1s | 双指针，正确 |
| max | direct | 32601 字 | 88.1s | 双指针，正确 |

**直接控制对 tokens 的影响是非单调的，取决于 baseline：**

- `effort=low`：模型原本会偷懒（848 字快速给答案）。直接控制命令它"列 2 种解法 + 分析复杂度 + 权衡"，**迫使展开**，思维链反而更长（17491 字）。
- `effort=max`：模型原本会疯狂发散（52509 字）。直接控制把它**收敛到规定的思考路径**，思维链更短（32601 字）。

**结论**：直接控制的本质是**规定"想什么"**，不是单纯省 tokens——

- baseline 偷懒 → 更多 tokens，但思考更完整、可控、可预期；
- baseline 发散 → 更少 tokens，思路更聚焦。

正确性不受影响（四种组合都解对）。复现脚本见 [`experiments/compare-direct.py`](../experiments/compare-direct.py)。

## 5. 环境敏感性（重要）

同一提示词，不同环境命中率差异巨大：

- 官方 App / Cherry Studio 等客户端：**稳定触发**（有客户端默认 system prompt + 深度思考开关 + 预设采样参数）。
- API 直调：默认参数下命中率飘（17%~100%），需手动配 `reasoning_effort=max` 等。

来源实测（2026-08-15，80aj）：同一开发者在 Cherry Studio 能稳定触发 `We need...` 思维链，在 Harness 平台却极难复现。排查结论是**客户端默认 System Prompt / 上下文环境的细微差别**，而非模型随机或 API 限制。

**含义**：标记命中不仅取决于提示词，还取决于运行环境。评估任何"思维链塑形"效果时，必须先固定环境。

## 7. 提炼出的设计原则

1. **标记要成为"说话人"，不要成为"流程步骤"**——单人流程标记必被省略。
2. **思考必须直接决定输出**——否则模型随时可以跳过思考结构。
3. **任务要有"可辩的分歧"**——没得辩的任务（如极简 fix），框架会被敷衍或泄漏到正文。
4. **表述"位置分离"，不表述"隐藏标记"**——说"在 think 内完成、不要留在最终回答"，不说"不要输出标记"。
5. **环境先行**——固定客户端环境后再谈命中率。
